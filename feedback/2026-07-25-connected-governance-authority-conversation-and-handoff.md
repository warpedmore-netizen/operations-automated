# Connected Governance authority, conversation and handoff

## Reported experience

Jamie found the proposed Operations Automated branding highly effective and described the overall workspace and audit history as beautiful.

The remaining problems were functional and explanatory:

- **Authority** still used specialist names and examples that did not resemble recognisable organisational structures;
- recommendations could be viewed and selected but not renamed, amended, supplemented, suggested or discussed;
- questions and feedback had to be taken out of the product and into a separate Codex conversation;
- the generated JSON package exposed an internal transport format without telling an ordinary user what to do next; and
- the interface did not clearly identify the honest stopping point while direct Workbench import remains unavailable.

## Operational insight

Human control is weakened when a user has to translate specialist governance language, accept a fixed system recommendation or handle an unexplained technical artefact. A governed product should make the decision understandable, allow the human to improve the proposed route and keep the resulting discussion beside the work.

## Strongest contextual interpretation

Jamie is not asking to remove authority boundaries, let AI approve its own work or bypass the private Workbench. The request is for a human-operable experience:

- start authority from familiar structures such as a founder, chief executive, executive team, board, committee or named owner;
- treat system recommendations as editable proposals rather than fixed answers;
- retain questions, suggestions and challenges on the page where they arise; and
- tell the user when they are finished instead of making JSON appear to be their responsibility.

The positive branding feedback is validation evidence, not approval of the separate draft brand system.

## Evidence, judgement and inference

### Recorded evidence

- The Authority page defined six role types but offered one specialist default model.
- Recommendation cards exposed only select, defer and reject decisions.
- No page retained a user question or product response.
- The primary final action downloaded `/api/governance-package`, even though direct import was explicitly inactive.
- The technical package is valid as a future machine hand-off but is not a useful ordinary-user outcome.

### Jamie's judgement

- Authority is difficult to understand and needs examples from real organisational structures.
- Recommendations need rename, add, suggest and discuss routes.
- Every page should support a two-way conversation.
- JSON without an instruction or supported next action is not a usable completion.
- The current visual brand should be preserved.

### AI inference

- Three progressive authority starters—founder-led, leadership-team and committee-led—are sufficient for this private pilot while retaining free text.
- Material recommendation edits should invalidate the previous selection and generated package.
- A retained page discussion can be introduced before a generative provider is connected, provided the response is clearly described as controlled guided logic rather than AI analysis.
- The JSON endpoint should remain available under an advanced disclosure for future integration, but it should not be the primary user action.

## Challenge tests

### Simplicity test

Adding more examples could make Authority more oppressive. The proposal uses three starter structures and plain questions, then permits direct amendment instead of adding a comprehensive organisation-design exercise.

### Authority test

Selecting a role example records language for proposed documents. It does not delegate authority, identify an approver or authorise publication.

### Contrary-evidence test

A free-form chat backed by deterministic guidance may look like generative AI without delivering it. The proposal labels the capability as a guided response, states that connected AI is inactive and makes no claim of open-ended analysis.

### Stale-decision test

If a selected recommendation is materially edited, its earlier selection no longer represents the same decision. The proposal clears that selection and any generated package.

### Handoff test

Hiding the technical package entirely would make future connection testing harder. The proposal retains it under an advanced section while telling ordinary users that they do not need to open or move it.

## Proposed response

- Replace specialist Authority headings with plain decision questions.
- Add founder-led, leadership-team and committee-led starter structures with recognisable examples.
- Allow recommendations to be renamed, rewritten and extended with user-created routes.
- Add a retained ask, suggest or challenge panel to every application page.
- Return page-specific controlled guidance without presenting it as connected generative AI.
- Make final draft review the primary human action and clearly state the current stopping point.
- Move the JSON package into an advanced future-import disclosure.
- Preserve the current proposed brand pilot.

## Decision state

This feedback justifies a proposed Connected Governance product change. It does not approve generated company policy, the brand system, a model connection, direct Workbench import, Confluence publication, Live promotion or external use.
