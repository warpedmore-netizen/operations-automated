# Guided question framing before answer

## Source and boundary

- **Source:** Jamie Peppard's answer to the high-consequence Ask-mode boundary test.
- **Question tested:** Whether Ask mode should recommend not proceeding when it lacks enough information to answer a high-consequence implementation question.
- **Permission to use:** Jamie continued the founder challenge and corrected the proposed Ask-mode behaviour.
- **Confidentiality boundary:** General methodology and hypothetical operational guidance only.

## Correction to the AI proposition

The previous proposition still assumed that Ask mode should answer the user's substantive implementation question. Jamie's correction is that Operations Automated should not manufacture a yes, no or implementation verdict when the information required to reach one has not been supplied.

Its immediate value is then to guide the user towards an answerable decision by:

- Explaining why the present question cannot yet be answered
- Identifying the material information, evidence and authority that are missing
- Reframing the broad or premature question
- Providing a proportionate structure the user can apply themselves
- Asking only the questions that could materially change the conclusion
- Offering a deeper assessment or project when the required work exceeds a short interaction

## Ask-mode answerability gate

Before giving a substantive answer, Ask mode should determine whether the available information is sufficient for the type and consequence of the decision.

Where it is sufficient, Operations Automated may give a proportionate methodology-based answer with its reasoning and limitations.

Where it is insufficient, the useful output is not a guessed answer. It is:

1. The current understanding of the intended outcome and decision.
2. A clear statement that the substantive question cannot yet be determined.
3. The smallest material evidence and questions needed to progress.
4. A decision structure, checklist or reframed question the user can use.
5. Any immediate boundary, such as not treating the conversation as implementation approval.
6. A route to continue in Ask mode or convert the record into an assessment or project.

## Guidance rather than delegated decision

Operations Automated helps the user understand how to examine, decide, improve and implement. It does not make an operational decision on behalf of the person or organisation, create authority from a chat answer or claim that a short interaction is a realised assessment.

This does not prevent AI from producing analysis, options, recommendations or implementation routes when evidence and authority are sufficient. It prevents the system from presenting those outputs as established when the necessary work has not been performed.

## Avoiding a question-only failure

Ask mode must not respond to every uncertainty with a long questionnaire. It should:

- Return the useful understanding already available
- Explain why each requested item matters
- Prioritise the smallest questions that could change the decision
- Supply a structure the user can use without the application
- Stop when specialist or authorised judgement is the real dependency

This preserves the approved output-contract principle that questions support value but are not the product by themselves.

## Disposition

**Material refinement to proposed Ask-mode behaviour.**

Replace the assumption that Ask mode always produces a direct answer with an answerability gate. Retain guidance, question framing and seamless continuation as valid useful outputs when a substantive answer is not justified.

## Retained lesson

Do not force an answer from an unready question. Help the user make the question answerable, show what the answer depends on and preserve the route into deeper work.
