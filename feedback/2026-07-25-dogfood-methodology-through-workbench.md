# Use the Workbench to create and assess the human methodology

## Source and boundary

- **Source:** Jamie Peppard after approving and merging the human-first Confluence publication model.
- **Context:** Selecting the first private implementation and feedback loop.
- **Permission to use:** Retain and use within Operations Automated methodology and product development.
- **Information boundary:** Controlled, non-confidential Operations Automated repository content and the existing private Confluence connection.
- **Authority boundary:** Jamie authorised preparation of another location in which the Workbench can create the methodology for assessment. Live Confluence creation remains subject to the approved preview, conflict check and exact plan-specific confirmation.

## Signal

Jamie proposed using the Workbench and its Confluence connection to create the human-readable methodology, then reviewing how well it performs. The resulting review should become the first feedback loop for both:

- the methodology and its presentation; and
- the Workbench process and publication capability.

## Operational interpretation

This is a dogfooding test: Operations Automated should use its own AI-led, human-controlled method to produce and evaluate its own delivery surface.

The test needs isolation. Publishing directly over the current 108 controlled pages would make it difficult to distinguish:

- content quality from migration behaviour;
- reader experience from repository traceability;
- a proposed synthesis from approved source meaning; and
- a successful technical write from a successful methodology outcome.

The smallest useful location is a separate top-level **Methodology Lab – Pilot 1** tree within the existing private Methodology space. It uses the approved connection without creating another credential, space or data source.

## Challenge and counter-test

### Strongest alternative

Create a new Confluence space dedicated to experiments.

### Why it is not the first recommendation

A new space adds permissions, ownership, navigation and eventual clean-up decisions before those differences create useful learning. A separate managed root tree provides sufficient isolation for the first pilot and leaves the existing pages unchanged.

### Failure test

The pilot would fail even if every page is created successfully when:

- Jamie cannot identify where to begin;
- the synthesis changes or overstates approved meaning;
- the complete method still feels like disconnected summaries;
- the practical chapter does not help a reader act;
- source and status information dominates ordinary reading;
- feedback cannot be separated into methodology, explanation and product signals; or
- the Workbench silently changes another managed page.

## Disposition

**Material product implementation proposal.**

Prepare:

1. a controlled ten-page Methodology Lab reading path;
2. a separate Workbench preview mode that targets only those pages;
3. a plan-specific confirmation phrase;
4. source maps linking every page to approved repository material;
5. a review page that begins the first feedback loop; and
6. an assurance pack and draft pull request.

Do not create the live Lab tree until the implementation is merged, a fresh plan shows its exact actions and Jamie enters the required confirmation.
