# AI Workbench — Product Purpose and Boundaries

## Control note

This is a proposed reconciliation of the approved Private OPERATE Workspace MVP purpose and later proposed Workbench learning. It does not approve the later implemented surface or change the approved Methodology.

## Why it exists

Provide a private, local-first operating and learning surface in which Jamie can apply, challenge, improve and release Operations Automated through AI-led, human-controlled work.

## Primary user

Jamie Peppard during the founder-controlled private-validation phase. Any broader user group requires a separate product, data, security and release decision.

## Core outcome

Jamie can see what needs attention, understand the relevant approved method and evidence, converse in context, make bounded Decisions and Approvals, hand authorised work to Codex, verify returned evidence and retain learning without operating developer tooling.

## What it includes

- My Work, Cases and connected operational records;
- the Operations Bible and Work Profiles;
- conversations, retrieval and exact knowledge snapshots;
- methodology challenges and feedback-to-change controls;
- Decisions, Approvals, Implementation Jobs and Codex handoffs;
- approved private Confluence evidence and Draft-publication controls;
- project, purpose, steering and prompt visibility; and
- local operational memory and recovery evidence.

## Boundaries and non-goals

The Workbench is not the Methodology, a methodology authority, the Dynamic Governance Tool, a general project-management suite, a customer production service or an autonomous release operator. It must not absorb unrelated products merely because shared implementation is convenient.

## Information boundary

SQLite holds private non-confidential operational memory. Credentials remain encrypted outside Git and outside SQLite. Customer, employer, client and third-party confidential data are excluded. Broader data use requires an explicit decision.

## Authority boundary

The Workbench may recommend, classify, prepare, record and execute already-authorised mechanics. Jamie retains Product Purpose, methodology meaning, consequential Decisions, Approvals, release, merge, Live promotion, external publication, spending, connections and risk acceptance.

## Relationship to the Methodology

The Methodology and Workbench remain in the Operations Automated core project because the Workbench is the current environment for applying and improving the Methodology. Git remains authoritative for controlled meaning; SQLite remains authoritative for local operational memory.

## Success evidence

The Workbench succeeds when it returns useful progress, keeps ownership and authority understandable, routes each request to the right product, uses exact purpose and prompt provenance, preserves specialist workflows and can recover its operational memory after failure.
