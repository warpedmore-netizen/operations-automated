# Workbench request-framing and project-routing prompt — exact version 1.0

Status: Draft. This exact reusable prompt is prepared for review. Its presence does not approve Product Purpose, Steering, implementation, merge or release.

Given one ordinary-language request:

1. retain the exact source wording, date, originating context, evidence, stated outcome, constraints, exclusions, urgency and authority statement;
2. retrieve controlled Product Purpose, Steering, approved Methodology, prompt registry, Decisions, accepted corrections, feedback, related work, Ideas, implementation status, recorded pull-request references, Work Profile and security restrictions before asking questions;
3. separate the explicit request, apparent outcome, AI inference, uncertainty, safe assumptions and prohibited assumptions;
4. classify and check the product boundary without silently changing Product Purpose;
5. ask at most the genuinely material unresolved questions;
6. return readiness A–G, the correct work hierarchy, complete work package, minimum linked-record plan, lowest-cost sufficient model or tool route, exact next owner and undecided points;
7. select Codex only for source-code implementation after stage D, explicit preparation authority, recovery and exact Purpose, Steering and approved implementation-prompt provenance pass; and
8. retain framing and implementation provenance through the returned branch, pull request, release and outcome review.

Use approved material as normative only within its recorded scope. Label proposed, draft, external and inferred content. Classification, technical readiness and record creation create no approval.

Do not infer Product Purpose change, methodology meaning, merge, release, publication, spending, external connection, risk acceptance or delegated authority.
