Two-minute guide

How the Workbench works

1

Choose your input

Type directly, attach a text/Markdown/CSV/JSON document, or select Record. The live level confirms that the microphone is receiving sound. Voice is transcribed first so you can correct it before any reasoning call.

2

Review or recover captured meaning

For voice, correct the original transcript. If transcription fails, the recording remains temporarily in that browser tab so you can retry without repeating yourself. Closing or refreshing the tab clears it.

3

Choose workspace and output

The workspace controls the type of repository guidance retrieved. Output type controls whether you receive an answer, summary, analysis, checklist, template or proposal-preparation brief.

4

Check before sending

You will see the estimated cost before anything is sent. Supporting evidence and technical details are available if you want them, but they do not interrupt the main answer.

5

Review and classify saved feedback

Open Was this useful? beneath an answer. Your reaction is stored under Saved feedback. Review it there and classify it as an answer correction, context, memory, evidence, a methodology candidate, a product candidate or no action.

6

Use the Decision inbox for controlled change

A candidate can be prepared, revised, rejected or deferred. Preparation creates an instruction for a new branch and draft pull request. Only a separate, explicit release decision by Jamie Peppard can authorise a methodology merge.

7

Ask for one useful challenge

Select Send me a challenge for a focused scenario and one primary question. You can target principles, AI suitability, deliberately manual work or the capability needed to deliver change with development teams.

8

Use evidence and publish readable documentation

Open Connections to synchronise evidence or preview the readable Methodology and Internal page tree. Review the create, update, unchanged and conflict results, open any affected page, and publish only after entering the exact plan-specific confirmation. That publication does not create methodology approval.

9

Use the Workbench from a phone

The private route keeps the local server on this computer and uses Tailscale HTTPS between authorised devices. The Workbench, computer and Tailscale must all remain running. Operational activation does not by itself record governance approval.

10

Review the shared brand visually

Open Brand review to see the logo, colour, typography, backgrounds and applied examples. A revision or rejection automatically enters the founder-feedback queue; Codex can prepare a response for your re-review, while overall brand approval remains a separate explicit decision.

Budgets

Soft limits warn; hard limits block paid API calls. Local records and retrieval remain usable. Limits can be changed in Settings.

What is retained

Conversations, reviewed transcripts, translations, extracted documents, feedback, proposals, decisions, repository references, implementation receipts, source references and usage are stored locally.

What is never automatic

Classification is not approval. Preparation does not edit main. AI cannot approve its own recommendation, and no change merges without Jamie Peppard’s explicit release action.

Automation is not the default

The methodology must also design work that remains manual, identify where human thinking is required and develop the teams and internal capability needed to operate the result.
