# Connected Governance dogfood pilot assurance pack

## Decision required later

After private review, decide whether the Connected Governance dogfooding increment is suitable for continued internal validation. This proposal does not request approval of the generated company policies.

## Current and proposed meaning

| Current | Proposed |
|---|---|
| The domain proof demonstrates connected obligations, controls, scenarios, findings and releases using fictional incident data. | Preserve that proof and add an Operations Automated business-governance dogfooding route. |
| The hosted interface assembles component names. | Assemble ten substantive, role-based proposed documents. |
| The Workbench and Connected Governance are described separately but their organisational relationship is implicit. | Record their distinct purposes, audiences, authorities and feedback routes. |
| The hosted product has no controlled write route. | Prepare a Draft hand-off while retaining the existing Workbench as the private publication boundary. |

## Evidence

- The fictional domain proof already tests candidate review, approval separation, immutable release, drift and scenario-derived findings.
- The private Workbench already retains a protected Confluence connection and conflict-aware publication.
- Founder feedback consistently requires AI-led creation, human-controlled meaning and readable documents that provide useful output.
- The first Confluence publication showed that a technically controlled mirror is insufficient without a deliberate human reading layer.

## Strongest alternative

Build a direct Confluence write connection into the hosted Connected Governance product immediately. This would produce a shorter visible route, but it would duplicate the existing private credential, expand permissions and combine product boundaries before the candidate documents and hand-off have been validated.

## Risks and controls

| Risk | Control |
|---|---|
| Generated prose is mistaken for approved policy | Every document is visibly proposed and targets Internal / Draft |
| Role language removes accountability | Reader prose uses roles; actual decisions retain the human actor |
| Product findings silently change methodology | Classify and route methodology candidates through the Workbench |
| The two prototypes diverge | Preserve the domain proof and document the hosted interface as the reader route |
| Draft publication overwrites a review edit | Reuse the Workbench's version comparison and conflict stop |
| The foundation appears complete | Treat it as a minimum candidate set and run scenario and reader review |

## Checks

- Build and test both governance implementations.
- Confirm the Operations Automated preset generates all ten candidate documents.
- Confirm no candidate document contains a standing personal owner.
- Confirm every generated document declares proposed status, authority and Draft destination.
- Confirm the branch does not change approved methodology meaning.
- Confirm no credential, token, confidential information or Live publication is introduced.

## Exact boundary

Approval of this proposal would permit continued private internal validation of the dogfooding workflow. It would not approve any generated company policy, methodology change, new connection, Live publication, external release, customer use or automatic regulatory monitoring.
