# Mobile knowledge workbench assurance pack

## Decision in one sentence

- **Decision required now:** review whether the proposed product direction correctly makes the Workbench the mobile knowledge-control surface.
- **AI recommendation:** approve the local interface correction; approve a bounded Jamie-only Tailscale pilot after its access policy is reviewed; reconcile the already demonstrated PR #18 Confluence Draft route into the ordinary knowledge journey without broadening its authority.
- **Current authority:** preparation only.

## What Jamie said and what AI inferred

- **Jamie said:** the Workbench is not being used because it is tied to the computer, difficult to read and hard to approve through. Its valuable job is spoken challenge and knowledge development, not product building.
- **AI inferred:** the product centre should be the challenge-to-knowledge-release journey. Mobile access is an activation requirement, not an optional convenience.
- **AI did not infer:** approval to install software, expose the local service, write review drafts to Confluence, merge or publish.

## Current approved position and proposed position

| | Current approved position | Proposed product position |
|---|---|---|
| Primary job | Private local AI conversation and governed repository/Confluence controls | Mobile-friendly challenge, knowledge development, readable decisions and controlled publication |
| Access | Server remains local; tailnet-only Serve is now operational evidence, but its governance approval is not inferred | Jamie-only private HTTPS phone pilot through Tailscale Serve |
| Review | Workbench brief and GitHub pull request | Workbench current-versus-proposed brief, GitHub trace and the bounded PR #18 Confluence Draft route |
| Authority | Git status authoritative; preparation, release and publication separate | Unchanged |
| Availability | Computer and local server must be running | Still true for the pilot; hosted service remains a later decision |

## Evidence and limitations

- **Recorded evidence:** broken live brand resources; unreadable transparent rail; missing image; unusable 390 × 844 layout; direct founder non-use; later tailnet-only phone access; and a first real phone recording that failed during transcription.
- **Related product evidence:** proposed draft PR #18 has already demonstrated AI-managed publication into Confluence Draft. It remains unmerged and does not change the current approved Workbench boundary.
- **User judgement:** Jamie values mobile spoken challenge and knowledge control more than product-building controls in this application.
- **AI inference:** a private tailnet is the proportionate first route.
- **Assumption:** Jamie is willing to install one private-network app on the computer and phone if the boundary is approved.
- **Limitations:** phone access has run, but the spoken challenge did not complete because transcription failed. A post-fix retry, access-denial test and independent-user test have not run.

## Strongest alternative

Build a fully hosted Workbench with application authentication.

This would remove the running-computer dependency and better support future users. It is not recommended first because it introduces materially larger authentication, data, hosting, security, privacy, cost, monitoring and incident obligations before founder value has been validated on mobile.

## Affected system

- Activation and first use
- Human-AI collaboration and challenge
- Output and approval comprehension
- Feedback-to-change governance
- Confluence reader and controlled-record layers
- Workbench brand, responsive layout and first-use guidance
- Identity, access, recovery and connection governance

The approved methodology baseline is not changed.

## Dependencies and contradiction checks

- **Git authority:** retained.
- **Approved versus proposed:** retained and made visible in the phone and Review Draft proposal.
- **Preparation versus release:** retained.
- **Release versus publication:** retained.
- **Confluence conflict protection:** retained.
- **Existing Draft-publication proposal:** PR #18 records standing founder authority for committed proposed content beneath the controlled private Draft parent. Reconcile it; do not create a second competing route or broaden its permissions.
- **Local credential storage:** retained.
- **Public exposure:** excluded.
- **Automatic publication:** excluded.
- **Automatic retrieval of Confluence interactions:** excluded.

The main tension is between a Confluence-first reading experience and Git-first authority. The proposal resolves this by treating Confluence as a labelled review or reading surface and Git as the source and release record.

## What could improve and what could become worse

- **Improve:** access, challenge cadence, voice use, comprehension, decision confidence, knowledge continuity and practical founder adoption.
- **Become worse:** attack surface, dependence on a running computer and third-party network, review-surface complexity, mobile-session risk and easier accumulation of API cost.

## Exact approval boundary

Approval of this assurance pack would authorise the proposed direction and later bounded implementation preparation. It would not by itself:

- install Tailscale;
- expose the Workbench;
- approve a tailnet policy;
- broaden the bounded Confluence Draft authority recorded in PR #18;
- change methodology meaning;
- merge the branch;
- publish a Live Confluence page; or
- publish externally.

Those remain named, separate control points.
