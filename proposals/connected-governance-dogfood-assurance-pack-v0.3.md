# Connected Governance conversational journey assurance pack

## Decision required later

After private use, decide whether the Connected Governance 0.3 authority, recommendation, discussion and handoff experience is suitable for continued internal validation.

This proposal does not ask Jamie to approve generated company policies, the draft Operations Automated brand, a generative AI connection, direct Workbench import or any Confluence publication.

## Trigger

Founder validation found that the 0.2 visual system and audit history were effective, but four human-use gaps remained:

1. Authority relied on specialist role names rather than familiar organisational examples.
2. Recommendations were explained but effectively read-only.
3. Discussion happened outside the product and was disconnected from the page that caused it.
4. The final primary action exposed JSON even though no supported user handoff existed.

The complete evidence and interpretation are retained in [OA-FEEDBACK-019](../feedback/2026-07-25-connected-governance-authority-conversation-and-handoff.md).

## Current and proposed experience

| Current 0.2 | Proposed 0.3 |
|---|---|
| One specialist authority model | Founder-led, leadership-team and committee-led starters plus editable role titles |
| Governance role labels | Plain questions about final say, day-to-day ownership, AI drafting and authorised execution |
| Select, defer or reject a recommendation | Rename, rewrite, reprioritise, change outputs, add another route or discuss it |
| A changed recommendation can leave old generated work visible | Material edits clear the previous selection and generated package |
| Feedback occurs in another conversation | Retained ask, suggest or challenge discussion on every page |
| No connected model, but no in-product response | Page-specific controlled guidance explicitly labelled as non-generative |
| JSON is the main handoff | Human review completion is primary; JSON is advanced future-import material |
| Direct import is inactive | The stopping point and later Workbench control are stated directly |

## Alternatives considered

### Add a more detailed authority guide

This would improve definitions but create another document to interpret. Three progressive starters and plain questions give immediate working examples without prescribing one organisational model.

### Allow comments but provide no response

This would retain evidence but not create the two-way experience Jamie requested. A bounded guided response gives immediate orientation while honestly disclosing that connected generative AI is not active.

### Connect a model immediately

This could provide richer discussion but introduces information exchange, cost, security, prompt and authority decisions that have not been approved. The proposed guided interaction tests the journey before that connection decision.

### Remove the JSON endpoint

This would simplify the interface but discard a valid future machine handoff. Moving it beneath an advanced disclosure preserves technical evidence without making it the user's task.

## Dependencies and residual gaps

- Free-form generative AI analysis is not connected.
- Direct hosted-to-Workbench import remains inactive.
- The current guided response does not edit documents or recommendations from conversation.
- A future model connection needs explicit purpose, information, permission, cost, safety, recovery and removal decisions.
- Independent-user, accessibility and ordinary small-screen validation remain necessary.
- The draft brand system remains a separate proposal despite strong positive founder feedback.

## Controls

- Role examples never delegate authority.
- A page discussion cannot approve, publish or silently change a recommendation.
- Material recommendation changes clear stale decisions and generated documents.
- All generated documents retain proposed status.
- The Confluence lifecycle remains fixed to Draft.
- No credential is requested, copied or stored in the hosted application.
- The technical handoff grants no approval, Live promotion, deletion or automatic publication.

## Checks required

- Production build, lint and automated interaction-contract tests.
- Full diff and status review.
- UK English and human-readable terminology review.
- Secret-pattern, confidential-information and accidental employer-specific-reference scan.
- Private owner-only deployment.

## Recommendation

Continue the existing draft proposal with Connected Governance 0.3 for private product validation.

Do not treat successful operation, positive brand feedback, saved discussion or selected documents as approval of policy, brand, AI connection, publication or external use.
